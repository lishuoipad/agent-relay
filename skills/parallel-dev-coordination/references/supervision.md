# 有界监督与主线程接续

这项机制配合现有主线程和已获授权的并行对话工作。主线程拥有交付接收、任务选择、文件归属及正式派工；并行对话更新自己的交付、等待条件和有效进展。安装或协调旁支只接线和验收，不承担永久调度，也不新建独立对话。已安装脚本不等于宿主已接通或监督已运行。

## 接入与实际运行

先明确目标ID、宿主、父子关系、任务绑定、通信及恢复授权、模型固定要求、开始/硬截止、停止入口。沿用现有任务账本的精确JSON字段映射，不解析长篇聊天猜测完成状态。记录主线程繁忙时可用的消息入口、在设备操作安全边界如何消费，以及谁承担观察。接口不可用时交付只读或提醒能力，不启动第二后端加载同一聊天。

支持两种接入方式，须分别验证：

- **工具宿主方式**：获准的主线程/宿主用 `wait_threads` 和每目标游标读取实时状态，`public_sample`去掉正文，将有界样本送入本地reducer。仅获得一次持久化通知许可后，宿主才调用原生消息工具。Python本身不能调用对话里的MCP工具。主线程直接观察，或临时复用已有闲置子智能体；接管者及范围留在原记录里。观察结束/宿主退出不自动续期。
- **兼容原生控制接口**：仅连接已存在、已加载目标的同一宿主。容量恢复另外使用 `capacity_recovery.py` v2及真实安全快照；主线程繁忙时的投递/消费能力需单独核验。私有stdio且无可用控制接口时，该恢复路径关闭。

`supervision.py` 是本地状态归纳与许可工具，不是常驻服务。它不会自行监视桌面、调用模型、发消息、选择新任务或改变Goal。外部调用者必须保持原生授权、鲜活读回和用户停止信号。它没有安装自动化、定时任务或hook；工具宿主停止调用后，不能宣称仍在后台监督。需要独立于模型的告警时，由宿主提供已验证通道；本地日志不能当作用户收到告警。

## 从待命到实际开工

现有记录每目标至少包含 `taskBindingId`、`taskState`、`assignmentState`、`decisionOwner`、具体`reason`、`nextReviewAt`（Unix秒）、相关依赖/冻结/批次/缺陷版本，以及已有决定/派工/产出证据引用。任务可以completed而执行者standby；已完成且没有下一批安排不当作容量故障。

待接收交付以项目记录的 `taskState=delivered_waiting_acceptance` 判断；宿主 `active` 可能只是等待轮次，不能遮蔽这一事实。暂停/人工输入、陈旧或错宿主样本、终态及既有失败容量保护仍优先。用 `deliveryRef={path,sha256}` 绑定冻结交付；相同哈希跨轮次、观察时间和审查进度更新保留同一事项，新交付哈希才产生替代事项。兼容旧单个 `evidence.sha256`；两者都没有时按同一任务绑定去重，因此替换交付必须补 `deliveryRef`，不能依赖聊天轮次推断版本。

主线程可在原任务/接收/待命节点增加以下可选字段，不改旧交付文件，不建第二账本：

```json
{
  "deliveryRef": {"path": "/existing/task/delivery.json", "sha256": "<frozen SHA256>"},
  "reviewProgress": {
    "deliverySha256": "<same frozen SHA256>",
    "updatedAt": "<actual observation time>",
    "summary": "已核验文件，语义复核仍进行中",
    "completedChecks": ["本次实际核验或有据复用的检查"],
    "remainingChecks": ["尚未完成的检查与范围"],
    "waitingOn": ["具体未满足条件、负责人和解除触发"]
  }
}
```

`project_record`、`observe` 返回和已有通知摘要会消费这些字段；进度只作上下文，不代表正式接收、不自动关闭事项或恢复Goal。只展示匹配当前交付哈希的进度，字段有界并标记截断；修改进度不重置通知身份/额度。已接收任务保持原终态，下一批等待继续写原 `reason` 和依赖字段；无需为了记录进度重开任务。实际主线程写入，执行者仍负责自己的交付和等待说明。不设统一审查工期，也不把正常设备/构建依赖当故障。

1. 主线程在较长测试/整合前、交付后，以及冻结解除、批次结束、新缺陷出现或复查到期时检查安排。冻结只限制明确文件/资源；不冲突的已授权诊断、返修和下一批准备单独评估。
2. 优先本地核对证据。有效等待且依赖未变不反复唤醒模型；已到期却没有新决定则形成一次待处理事项，采集器不得自己延长截止。
3. 主线程在当前不可中断操作完成后、下一段长操作开始前处理合并事项。无就绪任务记录具体依赖和下一复查；有就绪任务按原派工约定发送，避免与已有子智能体抢文件/设备。
4. 分别记录送达、确认、决定、正式派工和有效进展。收到提醒不关闭处理跟踪；决定后未行动也要复查。通知发送成功、对话active或准备了一份任务卡，均不能证明接续恢复。
5. 并行对话收到有效正式任务后开始获准范围；完成后交付并保留返修责任。缺任务时不自行扩Goal或不停发消息。任务绑定变更先核对授权和当前工作，旧错误不用于恢复新任务。

真实验收必须包含：主线程仍在手机测试，一项无冲突且已授权工作经安全边界评估后正式派发，目标实际推进；另验无就绪工作时的具体等待记录。仅通知送达的实现可以交付为监测功能，不能宣称已经解决并行停工。

## 持久状态、预算与未知结果

`supervision_store.py`仅管理自有SQLite文件。固定可信registry将逻辑run绑定到数据库路径和合同哈希；换目录、丢库、重启或修改合同均不能清零额度。原子事务共同预留：每故障3轮、每run6轮、故障失败链120次、run失败链120次（设计默认，更严格已有约束优先）。原失败链去重计入；每次额外尝试追加当前版本/模型路线已核实的上界。未知上界禁止恢复。保守预留不是实测模型调用或网络字节，也不限制所有成功工具循环。

监督主动发往模型处理通道的通知另计：默认每run12条、同接收者至少300秒间隔、最多60秒合并窗口。首次提醒、通知重试和模型通道升级都计数，即使目标已active。人类正常输入及合法正常开发派工不因通知额度耗尽而被阻断。相同未变化事项不重复发送；超额保留积压并使用已验证无模型通道给一次告警。

`reserve_*`只有首次持久化意图返回许可。超时、断线、崩溃或发送结果未知，不自动重发、不退款；先核实际新轮次和动作。局部锁/意图无法保证外部API恰好执行一次。每次派发前新鲜读取失败即停止；第二次失败阈值只影响显示，不允许使用旧缓存继续派发。

任务closed/superseded及已解决提醒不能被迟到事件重开。确认后的决定/行动有独立复查点；同一事件最多一次独立升级，不反复催促真实长操作或人工审批。

## 本地入口

使用绝对路径。合同及数据库只保存在本机获准任务输出，不发布真实线程ID或私有状态。明确初始化一次后，后续命令复用同一run/registry；已有状态不要删除重建。

```text
python supervision.py --db /absolute/state.sqlite3 --registry /fixed/registry --contract /absolute/contract.json --run-id authorized-run init
python supervision.py --db /absolute/state.sqlite3 --registry /fixed/registry --contract /absolute/contract.json --run-id authorized-run --input /absolute/public-samples.json observe
python supervision.py --db /absolute/state.sqlite3 --registry /fixed/registry --contract /absolute/contract.json --run-id authorized-run prepare
```

`prepare`只返回有界提议及有效期，不发送消息。调用者仅在`allowed:true`且仍新鲜、无新用户停止/审批时执行一次获准工具调用，然后通过`notification-result`记delivered/not_sent/unknown；未知不重试。后续使用`receipt`记录经独立核对的JSON证据、`overdue`产生待接入的无模型告警、`status`查看状态、`stop`停止。`status`含私有本机元数据，返回聊天前自行裁剪。

项目适配器只读指定JSON pointer，内容不完整或版本未知时禁自动动作；不按整个文件变化重测所有模块。证据引用的SHA只验证字节身份，调用者仍必须独立核实其业务含义，不能给任意`pass:true`文件贴哈希就宣布真实开工。

容量恢复的接入就绪、获准受限试运行与真实恢复通过分开：首次尝试不要求历史成功，但授权、全部安全检查、共享额度、模型及失败链证据必须齐全。子智能体只能由真实父线程使用其协作工具发送，先共享许可再新鲜claim；没有真实父线程接线时保留未启用，不把子智能体当独立聊天发送。

## 验证与交付

本地测试覆盖原子额度竞争、失败链限制、未知发送、重启、观察乱序/过期、待命变化、终态、通知合并及确认后跟踪；使用模拟快照，不调用真实模型。

分别报告代码测试、宿主观察、原生恢复接口、独立告警、繁忙主线程消费、实际派工及有效进展。缺少某条通路不妨碍交付已验证部分，但不能写成完整后台监督已上线。收尾将责任留给实际主线程，保存本次范围、停止方式、未验收项和有界证据。
