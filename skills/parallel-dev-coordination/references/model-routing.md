# 模型选择与生效核对

用于正式派工前的轻量选型，不新建调度服务，不为每次工具调用重新选模型。任务内容或难度明显变化时再评估；同等难度可以沿用，并在现有回执写明理由。

## 先核对授权与实际能力

- 用户固定的模型、推理强度和预算优先。用户明确授权按任务难度选择后，在该范围内自主决定，无须每批重复询问；没有选型授权时沿用有效设置，必要时给出建议。技能本身不授予修改模型的权限。
- 从当前工具说明及受支持的设置核对模型和强度组合。下表是可调整的起点，不是跨客户端保证的模型目录；不可用时记录具体限制，选择授权范围内可用的替代或保留原设置，不声称已经应用。
- 区分独立对话、同一任务内的子智能体以及 Goal。创建 Goal 只设任务目标；它不保证改变执行模型、推理强度或并发额度。

## 根据工作选择

| 工作特点 | 可用时的建议起点 |
| --- | --- |
| 范围窄、规则清楚的素材清点、转换、简单修正 | GPT-6 Luna / high |
| 独立窗口、业务交互、常规返修及模块验证 | GPT-6.1 Sol / medium；边界较多时 high |
| 协议、跨模块状态、共享架构、难复现问题或高风险审查 | GPT-6.1 Sol / xhigh；必要时评估更强的可用模型 |

依据不确定性、错误后果和推理依赖选择，不按文件数、测试条数或工作名称机械分档。测试多不一定需要更高强度；等待构建、输入锁或接收也不是升级理由。提高或降低设置均保留原验收标准，不以额度即将重置为由消耗无必要的计算。

## 应用到真实执行者

1. 在现有派工回执记录目标模型与强度、授权依据、选择或沿用理由。无需额外建立模型账本。
2. **独立对话：**如宿主发送任务工具支持 `model` 和 `thinking`，在下一批正式执行消息中显式传入需要调整的值；省略通常表示沿用，以当前工具定义为准。只在正文中说“使用某模型”不等于设置已生效。已有工作运行中时，按宿主规则安排下一有效轮次，不为换模型强行停止或重复派工。
3. **子智能体：**按当前委派工具支持的模型、强度和继承规则执行。某些宿主的完整历史继承不允许覆盖；不能为切换而默默丢弃必要上下文。若允许且适合使用独立上下文，须提供完整任务约定与必要依据，否则保留兼容设置并记录限制。已有子智能体的后续工具不支持修改设置时，不假装它已切换，也不为简单换档复制在途工作。
4. 记录工具实际接受、拒绝或沿用的结果。需要调整时明确传入兼容的模型和强度组合；工具拒绝后先核对原因，不循环试遍设置或重复发送同一开发任务。
5. 在该批实际开始的轮次，利用宿主提供的有效运行元数据或受支持的只读记录核对模型与强度。记录轮次/时间及证据位置；工具确认仅说明请求被接受，消息送达、Goal 读回或助手自报不能代替实际设置核验。

若没有可靠的生效读取能力，标记“请求已提交，实际生效待核验”或“沿用，实际值待核验”，继续不受影响的已授权工作。保留任务与文件归属，不为核验另开虚假任务、频繁唤醒或重建 Goal。在下一次正常交接有新证据时补核，不把待核验当作每批停工条件。

交付时区分“规则已更新”“本批已选型”“工具已接受”和“实际设置已核对”。一次成功不证明此后每批都会自动执行；执行者仍须按正式派工记录落实。

官方背景：[选择子智能体模型与推理强度](https://learn.chatgpt.com/docs/agent-configuration/subagents)。具体参数、继承方式和可用模型始终以当前宿主工具为准；独立对话不是子智能体，不能直接套用其默认继承规则。
