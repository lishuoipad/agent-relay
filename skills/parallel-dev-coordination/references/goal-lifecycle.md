# Goal 暂停与恢复保护

这项保护针对“旧暂停被下一轮重放、收到继续后仅恢复聊天却仍显示 Goal 暂停”。它与模型容量故障分开处理。

## 执行规则

- 只依据最新的人类控制要求；旧检查点、压缩摘要和工具返回不能重新授权暂停。收到暂停后及时执行并独立读回，随后停止目标工作。
- 新的继续撤销旧暂停；核对现有 Goal 的 ID、正文、预算和状态。恢复普通开发不等于 Goal 已恢复。当前工具只能暂停／完成／阻塞时，使用原生恢复控件；不得重建目标、重置预算或直接写数据库。
- Goal 状态、对话运行状态、实际开发产出分开记录。预算或用量限制仍按原生规则处理。

## 可选原生 hook

`scripts/goal_guard.py` 只读本机 `goals_1.sqlite`，在自己的小状态目录中记录控制摘要和工具读回，不访问网络、不调用模型、不存储完整提示或目标正文。安装时绑定确切的父对话 ID 和 transcript 路径，其他对话／子会话不处理。

原生 `UserPromptSubmit` 捕获新指令；`PreToolUse` 检查 `update_goal(status=paused)`，允许绑定本轮、现有 Goal、180 秒以内且未使用的新暂停指令。新的用户输入、Goal 激活、会话恢复／压缩、Interrupt、目标变化或无法核对的历史使旧许可失效。每条许可只允许一次操作，之后只读回，不盲目重复。

确定性识别只接受整条简短指令，例如“先暂停”“暂停开发”“继续”“恢复目标”，不从引用文字或复合句推断授权。其他表达仍可用原生 Goal 控件。保护不会自行恢复或暂停 Goal。

脚本检查当前 transcript 增量最多 4 MiB；超过限制或格式不明拒绝模型的暂停调用，不扫描完整长会话。实现使用当前本机 SQLite／transcript 格式，升级后必须重新验证。原生 hook 启动失败、超时、未受信任、宿主绕过 hook，以及检查与实际写入之间的竞态仍无法由外部脚本完全消除；这不是原生状态机修复或绝对防护。

## 安装和启用

先把脚本安装到当前本机技能目录，再从该目录运行 `scripts/install_goal_guard.py`，传入 `--python`、`--codex-home`、`--state-dir`、`--backup-dir`、`--thread-id` 和 `--transcript-path` 的真实值。所有路径必须是绝对路径；当前安装器拒绝空格及 shell 元字符，避免依赖不一致的宿主 shell 引号规则。仅合并该目标的 5 个事件处理器，保留其他用户 hook 与已有项目续接 hook，原文件备份并记录哈希。

安装器**不会信任自身**，不会更改 `config.toml` 的 hook trust，不会模拟 managed 来源。通过原生 `/hooks` 或宿主提供的 Hooks 审核界面，审查并信任名称为 `Agent Relay Goal guard [目标ID]` 的精确定义。定义带脚本 SHA256；代码变化后需重新生成定义和审核。

分别验证文件安装、原生发现、受信任、真实事件执行和行为结果。先用正常 `get_goal` 调用确认原生 hook 运行及状态读回；不要为测试而暂停正在工作的生产 Goal。本地注入测试只能证明脚本行为，不能代替原生执行证据。没有原生审核或实际事件记录时标记“已安装，尚未确认生效”。

## 回退

先通过原生 Hooks 界面禁用这 5 个处理器。核对安装回执与当前文件，移除本安装器写入的对应目标处理器；仅在文件未被其他任务更新时才可恢复整份备份。保留运行记录用于排查。不删除或改写真实 Goal、rollout 和其他 hook。

官方接口与审核规则：[Codex Hooks](https://learn.chatgpt.com/docs/hooks)。
